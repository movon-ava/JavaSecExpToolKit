# Spec Delta: services/malicious-server

## Purpose

规定恶意服务器能力：真实启停监听端口、把已构建的载荷发布上去、并给出目标可用的回连地址。
该能力用于授权的内网测试，只负责「监听与发布」，不主动向任何目标发送载荷。

## ADDED Requirements

### Requirement: 五类服务可独立启停

系统 SHALL 支持 JNDI、HTTP、TCP、FakeMySQL、JRMP 五类服务各自的启动与停止，
且每类服务的监听参数可独立配置。

#### Scenario: 启动一类服务
- **WHEN** 使用者选定一类服务并点击启动
- **THEN** 该类服务在配置的地址与端口上真实监听
- **AND** 界面显示其运行状态与实际绑定端口

#### Scenario: 停止一类服务
- **WHEN** 使用者对运行中的服务点击停止
- **THEN** 该类服务释放端口
- **AND** 界面状态回到未启动

#### Scenario: 未启动的服务不可停止
- **WHEN** 某类服务处于未启动状态
- **THEN** 停止操作不可用，而不是给出一个无意义的失败

### Requirement: 端口绑定必须按服务类型使用正确的键名

系统 SHALL 按服务类型下发正确的端口键。非 JNDI 服务的端口键为单一主端口；
JNDI 服务使用各自的协议端口键。键名错误时不得静默降级为默认端口。

#### Scenario: 非 JNDI 服务只下发主端口
- **WHEN** 启动 HTTP、TCP、FakeMySQL 或 JRMP 中的任一类
- **THEN** 下发的端口键是主端口键
- **AND** 界面上配置的端口即实际绑定的端口

#### Scenario: 可选端口未填写时不参与启动
- **WHEN** JNDI 的可选端口（需要额外证书配置的一项）留空
- **THEN** 该端口不参与启动配置
- **AND** 若因此避免了启动被拒，启动结果必须是成功而不是失败

### Requirement: 载荷可按协议发布并取得回连地址

系统 SHALL 允许把已构建的载荷发布到已启动的服务上，并按协议返回目标可直接使用的回连地址。

#### Scenario: 发布对象形态载荷
- **WHEN** 向只接受对象形态的协议发布载荷
- **THEN** 发布成功并返回该协议的地址

#### Scenario: 载荷类型与协议匹配
- **WHEN** 待发布载荷的类型不被目标协议接受
- **THEN** 发布失败并给出可读原因
- **AND** 不得把类型不符当成成功

#### Scenario: JNDI 给出多个入口
- **WHEN** 向 JNDI 发布载荷并取回地址
- **THEN** 返回的地址包含该服务实际启用的各协议入口
- **AND** 地址可直接复制使用，不需要使用者自己拼装

### Requirement: 监听参数可长期保存

系统 SHALL 把绑定地址、公布地址与各服务端口作为可持久化配置保存，并在下次进入页面时预填。

#### Scenario: 端口初值来自配置
- **WHEN** 配置中保存了某类服务的端口后重新进入服务页
- **THEN** 端口输入框的初值取自配置
- **AND** 配置保存后无需重启程序即生效

#### Scenario: 非法端口输入被容错
- **WHEN** 配置里的端口为空、非数字或超出合法范围
- **THEN** 该端口按未配置处理，沿用默认值
- **AND** 不得因此抛出异常或启动到错误端口

### Requirement: 载荷发布与本地构建共用同一条链路径

系统 SHALL 让服务页的载荷构建与载荷生成页使用同一个构建入口，
避免出现「生成页能产出、发布却报类型不符」的不一致。

#### Scenario: 服务页复用生成页的链规则
- **WHEN** 使用者在服务页追加、删除或清空链节点
- **THEN** 链规则与载荷生成页完全一致（载体不可移除、只接受引擎认可的后继节点）

#### Scenario: 从预设直接发到服务页
- **WHEN** 在预设链页点击「发到恶意服务器」
- **THEN** 服务页收到该预设的载体、链与参数
- **AND** 使用者的其它编辑不被覆盖

### Requirement: 退出时释放全部端口

系统 SHALL 在程序退出前停止全部已启动的服务。

#### Scenario: 关闭窗口释放端口
- **WHEN** 使用者关闭主窗口
- **THEN** 五类服务全部被停止
- **AND** 再次启动程序不会因端口被占用而失败

### Requirement: 状态呈现反映真实运行情况

系统 SHALL 在界面上如实显示每类服务的运行状态、绑定地址与已发布载荷条数；
失败时必须给出可读原因，而不是静默失败。

#### Scenario: 查看全部服务状态
- **WHEN** 使用者刷新状态
- **THEN** 五类服务各显示一行状态
- **AND** 已发布载荷的服务显示其条数

#### Scenario: 启动失败给出原因
- **WHEN** 启动因端口被占用或配置被拒而失败
- **THEN** 界面显示失败原因
- **AND** 状态回到未启动，而不是停留在「启动中」
