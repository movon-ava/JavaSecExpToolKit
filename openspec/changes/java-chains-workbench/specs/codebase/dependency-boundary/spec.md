# Spec Delta: codebase/dependency-boundary

## Purpose

在上一轮已接纳通用载荷生成包的基础上，继续接纳本次新增的服务端适配包与预设读取包，
使「是否被正确解耦」对新增代码同样可机械判定。其余约束
（无环、叶子层无出边、共享内核单向被依赖、通用组件不依赖具体功能模块、边界检查可机械执行）
保持不变。

## MODIFIED Requirements

### Requirement: 包级依赖必须符合声明分层

系统 SHALL 只允许声明过的包间依赖方向。允许的方向为：
界面层依赖探测 / 代理 / Shiro / 载荷生成 / 服务端适配 / 预设读取 / 漏洞分析 / 配置 / 工具；
探测与 Shiro 依赖工具；Shiro 额外依赖载荷生成；载荷生成依赖工具；
服务端适配只依赖载荷生成；漏洞分析编排层只依赖分析内核；
配置、代理、工具不得依赖其它项目包。

此外，共享内核（工具包与配置包）SHALL 允许被任意包依赖：
内核自身不含任何项目内依赖，因此这条放宽不会引入环，也不会让任何模块获得反向感知能力。
判定上等价于「任意包的允许目标集合里都包含内核」。

不允许依赖具体功能层的约束不变：只承载机制的包不得依赖功能模块，
叶子包不得依赖功能层。

#### Scenario: 叶子层保持无出边

- **WHEN** 检查配置、代理、工具三个包的 import 与限定名引用
- **THEN** 三者对其它项目包的依赖数为零

#### Scenario: 未声明的依赖方向被拒绝

- **WHEN** 某次改动让工具包依赖了 Shiro 包
- **THEN** 自检失败并给出该依赖所在的文件与行号

#### Scenario: 新增的预设读取包保持无出边

- **WHEN** 检查预设读取包内全部源文件
- **THEN** 该包对其它项目包的依赖数为零

#### Scenario: 叶子包可依赖共享内核

- **WHEN** 检查代理包或分析内核包内全部源文件
- **THEN** 其中只允许出现对共享内核的引用
- **AND** 不出现对任何功能层的引用

#### Scenario: 叶子包依赖功能层被拒绝

- **WHEN** 某次改动让代理包依赖了载荷生成包
- **THEN** 自检失败并给出该依赖所在的文件与行号

#### Scenario: 放宽后仍无环

- **WHEN** 对 `src/` 下全部 Java 源文件做依赖分析
- **THEN** 包级依赖图中不存在任何环

#### Scenario: 服务端适配不反向依赖界面

- **WHEN** 检查服务端适配包内全部源文件
- **THEN** 其中不出现对界面包的任何引用
- **AND** 该包只允许依赖载荷生成能力与共享内核

#### Scenario: 界面控制器之间无反向依赖

- **WHEN** 检查界面控制器之间的构造参数与字段类型
- **THEN** 依赖方向只允许「抓包 → 探测 / Shiro」「代理 → 抓包 → 配置」，
  不存在两个控制器互相持有对方实例

### Requirement: 通用组件不得依赖具体功能模块

系统的通用组件 SHALL 不依赖任何具体功能模块，使其可在不同功能之间复用。

通用性判定标准：该组件封装的是与具体漏洞类型无关的机制（序列化、编解码、链式构建、载荷生成），
而非某一漏洞的专用逻辑。判定范围包括既有通用链引擎与载荷生成组件。

#### Scenario: 通用链引擎可独立复用
- **WHEN** 检查 Shiro 包中的通用链封装层
- **THEN** 该文件不出现对 Shiro 专用引擎类的任何引用
- **AND** 其 Base64 编码能力来自共享内核而非具体功能模块

#### Scenario: 载荷生成组件可独立复用
- **WHEN** 检查承载载荷生成能力的包内全部源文件
- **THEN** 其中不出现对 Shiro、探测、代理、界面四个包的 import 与限定名引用

#### Scenario: 新增页面不得被引擎反向引用
- **WHEN** 检查载荷生成与 Shiro 包内全部源文件
- **THEN** 其中不出现对本次新增页面类的引用

#### Scenario: 断言范围只增不减
- **WHEN** 对比本次改动前后的依赖边界自检用例
- **THEN** 用例数不少于改动前
- **AND** 规则文件的两份副本（测试与审计脚本）保持一致
