# Spec Delta: ui/analyze-pages

## Purpose

规定漏洞分析两个二级项各自的页面职责与相互边界：依赖口径与代码口径必须是两个可区分的页面，
且各自的结论、控件与建议动作不得互相覆盖。

## ADDED Requirements

### Requirement: 两个二级项对应两个不同的页面

系统 SHALL 让「组件与漏洞」与「调用链查询」打开两个内容不同的页面，且两者的标题、
副标题、控件集合与报告区互相独立。

#### Scenario: 打开组件与漏洞
- **WHEN** 选择「组件与漏洞」
- **THEN** 内容区出现依赖口径的标题与副标题
- **AND** 不出现调用链口径的控件（建库、查询、特征匹配）

#### Scenario: 打开调用链查询
- **WHEN** 选择「调用链查询」
- **THEN** 内容区出现代码口径的标题与副标题
- **AND** 不出现依赖口径的控件（pom 路径、本地依赖分析）

#### Scenario: 两页内容可区分
- **WHEN** 分别采集两页的全部标签文字
- **THEN** 两个集合不相同

#### Scenario: 报告区互不覆盖
- **WHEN** 在一页产出报告后再切到另一页
- **THEN** 另一页的报告区内容不受影响

### Requirement: 代价在页面上被表达出来

系统 SHALL 让需要外部引擎的分钟级动作只出现在「调用链查询」页，且该页在发起前要求显式超时。

#### Scenario: 依赖口径页永远是秒级动作
- **WHEN** 查看「组件与漏洞」页的可执行动作
- **THEN** 只包含本地依赖分析，不需要任何外部程序

#### Scenario: 建库动作要求超时
- **WHEN** 在「调用链查询」页填写的超时低于下限
- **THEN** 动作被提前拦下并给出可读原因

### Requirement: 建议动作渲染到各自页面

系统 SHALL 把报告里的建议按钮渲染到产出该报告的页面自己的容器里。

#### Scenario: 依赖口径的建议留在本页
- **WHEN** 本地依赖分析产出带建议的结论
- **THEN** 建议按钮出现在该页的容器内
- **AND** 点击后跳到建议指向的功能页

#### Scenario: 两页的按钮容器互不干扰
- **WHEN** 两页先后各自产出建议
- **THEN** 后产出的一页不会清空另一页已经渲染的按钮

### Requirement: 可持久化的分析配置

系统 SHALL 把分析相关的默认值保存在配置文件中，包括默认扫描目标、外部引擎、工作目录、
超时、反编译输出目录与外部 gadget 规则文件。

#### Scenario: 默认值在进页时生效
- **WHEN** 在配置页保存默认扫描目标后重新进入分析页
- **THEN** 目标输入框预填该值

#### Scenario: 外部规则文件留空
- **WHEN** 外部 gadget 规则文件留空
- **THEN** 分析只用内置规则表且不报错
