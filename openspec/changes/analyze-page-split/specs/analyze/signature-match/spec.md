# Spec Delta: analyze/signature-match

## Purpose

规定「把代码特征翻译成可能的漏洞类型与绕过手法」这一能力：输入是调用图数据库，
输出是判定结论而不是事实清单。

## ADDED Requirements

### Requirement: 特征匹配输出漏洞类型与绕过手法

系统 SHALL 把数据库中的代码特征与签名库对照，输出可能的漏洞类型、每类的触发条件、
命中依据与该类型下常见的绕过手法。

#### Scenario: 命中后给出类型与绕过手法
- **WHEN** 库中出现签名库登记的高危调用特征
- **THEN** 报告按漏洞类型聚合展示
- **AND** 每个类型给出触发条件、命中依据与绕过手法清单

#### Scenario: 未命中时说明边界
- **WHEN** 库中没有任何特征命中
- **THEN** 报告明确说明「未命中不代表没有漏洞」

#### Scenario: 按严重度过滤
- **WHEN** 指定只保留高危特征
- **THEN** 报告只包含高危命中
- **AND** 过滤后为空时给出可读说明而不是空报告

#### Scenario: 省略绕过手法
- **WHEN** 请求不输出绕过手法
- **THEN** 报告标题与内容都不再声明含绕过手法
- **AND** 漏洞类型与命中依据仍然保留

### Requirement: 命中依据可回溯

系统 SHALL 为每条命中给出特征标识、特征分类、所属漏洞类型与命中样例。

#### Scenario: 命中明细含特征标识
- **WHEN** 查看命中明细
- **THEN** 每条命中给出严重度、特征标题、特征标识与命中数量

#### Scenario: 未命中的特征也要列出
- **WHEN** 查看报告末尾
- **THEN** 列出未命中的特征标识，以便确认确实跑过而不是漏跑

### Requirement: 数据库缺失时给出可读结论

系统 SHALL 在数据库不存在时给出「先构建数据库」的可读提示，且不得以空报告冒充成功。

#### Scenario: 数据库缺失
- **WHEN** 数据库文件不存在
- **THEN** 报告的结论段说明找不到数据库并指向调用链分析
- **AND** 该次动作被标记为未成功

### Requirement: 签名库的失败必须可见

系统 SHALL 在签名库缺失、格式非法、正则非法或特征指向未登记类型时报错，
不得静默跳过单条特征。

#### Scenario: 签名库缺失
- **WHEN** 指定的签名库文件不存在
- **THEN** 报告给出可读原因

#### Scenario: 单条特征非法
- **WHEN** 任意一条特征的正则非法或指向未登记的漏洞类型
- **THEN** 整次匹配失败并指出是哪一条
