# Spec Delta: codebase/dependency-boundary

## Purpose

规定本仓库 Java 代码的包级依赖边界，使「是否被正确解耦」成为可机械判定的客观事实。
本次只扩展声明分层与「通用组件不得依赖具体功能模块」两处的判定范围，
使其接纳新引入的通用载荷生成能力；其余约束（无环、叶子层无出边、共享内核单向被依赖、
边界检查可机械执行）保持不变。

## MODIFIED Requirements

### Requirement: 包级依赖必须符合声明分层

系统 SHALL 只允许声明过的包间依赖方向。允许的方向为：
`ui` 依赖 `probe` / `proxy` / `shiro` / `payload` / `config` / `util`；
`probe` 依赖 `util`；`shiro` 依赖 `util` 与 `payload`；`payload` 依赖 `util`；
`config`、`proxy`、`util` 不得依赖其它项目包。

新增的通用包必须出现在允许方向表中，且只能依赖共享内核；
具体功能模块可以依赖它，它不得依赖任何具体功能模块。

#### Scenario: 叶子层保持无出边
- **WHEN** 检查 `config`、`proxy`、`util` 三个包的 import 与限定名引用
- **THEN** 三者对其它项目包的依赖数为零

#### Scenario: 未声明的依赖方向被拒绝
- **WHEN** 某次改动让 `util` 依赖了 `shiro`
- **THEN** 自检失败并给出该依赖所在的文件与行号

#### Scenario: 新增通用包保持单向
- **WHEN** 检查承载载荷生成能力的包内全部源文件
- **THEN** 该包只依赖共享内核
- **AND** 具体功能模块依赖它是允许的，方向不得反向

#### Scenario: 界面控制器之间无反向依赖
- **WHEN** 检查界面控制器之间的构造参数与字段类型
- **THEN** 依赖方向只允许「抓包 → 探测 / Shiro」「代理 → 抓包 → 配置」，
  不存在两个控制器互相持有对方实例

### Requirement: 通用组件不得依赖具体功能模块

系统的通用组件 SHALL 不依赖任何具体功能模块，使其可在不同功能之间复用。

通用性判定标准：该组件封装的是与具体漏洞类型无关的机制（序列化、编解码、链式构建、载荷生成），
而非某一漏洞的专用逻辑。判定范围包括既有通用链引擎与本次新增的载荷生成组件。

#### Scenario: 通用链引擎可独立复用
- **WHEN** 检查 `shiro` 包中的 java-chains 封装层
- **THEN** 该文件不出现对 Shiro 专用引擎类的任何引用
- **AND** 其 Base64 编码能力来自共享内核而非具体功能模块

#### Scenario: 载荷生成组件可独立复用
- **WHEN** 检查承载载荷生成能力的包内全部源文件
- **THEN** 其中不出现对 `shiro`、`probe`、`proxy`、`ui` 四个包的 import 与限定名引用

#### Scenario: 断言范围只增不减
- **WHEN** 对比本次改动前后的依赖边界自检用例
- **THEN** 用例数不少于改动前
- **AND** 新增用例在人为引入反向引用时确实失败，证明不是恒真断言
