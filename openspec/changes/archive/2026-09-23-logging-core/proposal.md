# Proposal: 日志内核（按日期分文件 + 定期清理）

## Why

程序目前在**任何**异常路径上都不留痕迹：源码里 107 处 `catch` 中有大量以「忽略」结尾，
异常被吞掉、流程继续走，使用者看到的是「点了按钮没反应」。排错时能拿到的线索只有
界面上一行提示，无法回答「是哪一步失败、抛了什么」。

更麻烦的是后台线程：代理的转发线程、隧道泵、引擎输出读取线程都不在界面线程上，
它们的异常既不会弹窗也不会写文件，进程照常运行——这类问题只能靠复现时人工盯着，
而使用者报告现象时现场早已消失。

因此需要一个**始终可用、绝不拖累主线**的记录通道：把异常与关键动作落到文件里，
按天分开（方便定位「哪一天出的问题」），并定期清理（不让日志无限增长）。

## What Changes

- 新增日志内核：一条记录通道承载级别过滤、时间戳、线程名与异常栈展开。
- 日志按日期分文件，文件名携带当天日期；跨天时自动切换到新文件。
- 日志目录按「环境变量 > 配置项 > 用户目录默认值」三级解析。
- 新增保留天数策略：只清理本工具自己命名的日志文件，逐项校验目标落在日志目录内；
  启动时清理一次，跨天切换文件时再清理一次。
- 写入动作对外绝不抛出：磁盘满、目录不可写、文件被占用都只丢弃这一条记录。

## Capabilities

### New Capabilities

- `codebase/logging`：文件日志内核（级别、按日分文件、保留清理、失败静默）。

## Non-goals

- **不做日志查看器**：本工具不提供界面内的日志浏览，日志就是普通文本文件。
- **不做轮转压缩与归档**：只做「保留最近若干天」，不做打包、不迁移历史。
- **不接管标准输出**：不重定向既有打印，控制台回显只是可选项。
- **不改变既有功能**：探测、代理抓包、抓包转换、Shiro 利用、Payload 生成、预设链、
  toString 链、带外 Jar、恶意服务器、文件上传、漏洞分析的行为一律不变。
- **不新增第三方依赖**：只用 JDK 标准库，不在 `src/pom.xml` 引入任何新依赖。
