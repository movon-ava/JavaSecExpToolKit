# Proposal: 把既有静默失败路径接入日志

## Why

日志内核只是通道，通道空着就解决不了任何问题。本轮真正要做的是**把已经吞掉的信息吐出来**：
代理转发失败、进程树终止失败、引擎超时、Shiro 探测请求异常、载荷构建钩子失败，
这些位置当前都以「忽略」结尾，使用者只看到「没反应」。

接入的取舍是「只补已有失败路径，不重写正常路径」：既有语义与返回值一律不动，
只在原本就要丢弃异常的地方先记录一行，然后继续按原逻辑走。

## What Changes

- 代理：连接处理、隧道转发、监听循环、上游连接失败的异常被记录；监听启动 / 停止记录一行。
- 载荷：构建失败、节点查询失败、指标与上下文读取失败、步骤钩子失败被记录。
- Shiro：探测请求异常（含响应体读取）被记录；密钥字典读取失败被记录。
- 漏洞分析：引擎与脚本的输出读取中断、超时终止、临时目录清理失败被记录；
  引擎超时按「超时」而非「失败」记录，与报告的结论口径一致。
- 启动预热：单步失败记录异常类型与栈，并保留既有「不让程序起不来」的行为。
- 新增一套 Java 自检覆盖内核的规则层与写入层；新增 Python 单测覆盖纯规则边界。

## Capabilities

### New Capabilities

- `codebase/logging-integration`：既有失败路径的记录点与判定标准。

## Non-goals

- **不改任何失败路径的行为**：返回值、抛出与否、界面提示文字一律不变，只增加记录。
- **不给正常路径加日志**：成功路径不新增逐条记录，避免日志量失控。
- **不记录报文内容**：请求体、响应体、密钥等敏感内容不进日志。
- **不改变既有功能**：全部功能的对外行为不变。
