# process/multi-agent-concurrency Specification

## Purpose

规定多 Agent 并行开发时的隔离与协作边界，使「互不干扰」成为可核对的客观事实，
而不是依赖执行者自觉。适用于本仓库全部角色化 agent 会话。

## Requirements

### Requirement: 每个 agent 必须拥有独立工作区

系统 SHALL 让每个执行角色的 agent 运行在独立 Git worktree 与独立分支上，
使任一 agent 的文件改动对其它 agent 不可见。

#### Scenario: worktree 内改动不影响主仓库
- **WHEN** 某 agent 在其 worktree 内修改或新建文件
- **THEN** 主仓库对应路径的内容与 `git status` 输出均不发生变化

#### Scenario: 并发提交互不覆盖
- **WHEN** 两个 agent 同时运行并各自提交
- **THEN** 每个 agent 的提交只出现在自己的分支上，两条分支的提交记录互不影响

### Requirement: 写入域必须机械校验

系统 SHALL 在提交 agent 产出前，将其改动的每个文件与角色写入域矩阵比对，
只提交落在写入域内的改动。

#### Scenario: 越界改动被拒绝提交
- **WHEN** 某 agent 改动了不在其写入域内的文件
- **THEN** 这些改动不被提交，暂存被撤回，并列出越界文件路径

#### Scenario: 域内改动正常提交
- **WHEN** 某 agent 的改动全部落在其写入域内
- **THEN** 改动被提交到该 agent 的分支

### Requirement: 监督角色必须只读

系统 SHALL 以只读沙箱运行监督角色，使其在技术上无法修改仓库，
以保证审计独立性不依赖纪律约束。

#### Scenario: 只读会话无法写文件
- **WHEN** 监督角色尝试创建或修改文件
- **THEN** 写入被拒绝，且工作区与仓库内容保持不变

#### Scenario: 监督角色仍可读取分支差异
- **WHEN** 监督角色需要审计某执行角色的产出
- **THEN** 它能在只读沙箱下读取分支与主线的差异、提交记录与文件内容

### Requirement: 角色会话必须有超时上限

系统 SHALL 为每个角色会话设定超时上限，使运行过久的会话能被终止并保留判断依据。

超时时系统必须终止该会话及其子进程，并保留现场与日志；
不得在未完成的情况下将产出视为可用结果。

#### Scenario: 超时会话被终止
- **WHEN** 角色会话运行时间达到超时上限
- **THEN** 该会话及其子进程被终止，且打印出超时提示与日志尾部

#### Scenario: 超时不会污染仓库
- **WHEN** 会话因超时被终止
- **THEN** 未完成的改动不会被提交，现场保留在该会话的独立工作区中

### Requirement: 全仓库共享资源不得并发修改

系统 SHALL 将面向全仓库的收尾动作排除在并发窗口之外，由主 agent 在合并后统一执行。

收尾动作包含：写入备份快照目录、追加改动报告、更新阶段进度、重新构建产物。

#### Scenario: 并发期间不触碰共享资源
- **WHEN** 两个及以上 agent 同时运行
- **THEN** 没有任何 agent 写入备份目录、改动报告、进度文件或构建产物

#### Scenario: 合并后统一收尾
- **WHEN** 各执行角色的分支已合并
- **THEN** 备份、报告、进度与构建由主 agent 依次执行，且备份目录只保留最近三次快照
